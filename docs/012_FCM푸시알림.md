# 012. FCM 푸시 알림 + 가격 체크 봇

## 상태: ⏸ 대기 (파트너스 API 승인 후 재개)

### 비활성화 사유 (2026-03-15)
- PriceChecker 비활성화: 쿠팡이 맥미니 IP를 403 차단 + iOS Universal Link로 쿠팡 앱 자동 열림
- 대안: 상세 페이지 수동 새로고침 버튼 (CoupangScraper 1회 트리거)
- 파트너스 API 승인 → 서버사이드 가격 조회 API로 전환 예정

## 아키텍처 개요

```
[앱 포그라운드 체크] (⚠️ 비활성화 — iOS Universal Link 문제로 중단)
  ├─ PriceChecker 컴포넌트 주석처리 (index.tsx)
  ├─ iOS에서 WebView가 쿠팡 앱을 열어버리는 문제 → 모든 우회 방법 실패
  ├─ 대안: 상품 상세 페이지에서 수동 새로고침 버튼 (1회 가격 체크)
  └─ 파트너스 API 승인 후 서버사이드 가격 조회로 전환 예정

[수동 가격 새로고침] (현재 방식)
  ├─ 상세 페이지 헤더 새로고침 아이콘 탭
  ├─ CoupangScraper Hidden WebView로 1회 스크래핑
  ├─ 성공 시 currentPrice + priceHistory 업데이트
  └─ 15초 타임아웃, 실패 시 알림 표시

[GitHub Actions Cron] (파트너스 API 키 발급 후 전환 예정)
  ├─ 쿠팡 파트너스 API로 가격 조회 (서버사이드 스크래핑 불가 — Access Denied)
  ├─ Firestore priceHistory 업데이트
  ├─ 가격 하락 → Expo Push 발송
  └─ 코드 준비 완료 (scripts/price-checker/), API 키 대기
```

### 서버사이드 스크래핑 불가 경위
- Puppeteer + stealth plugin으로 GitHub Actions에서 시도
- 쿠팡이 GitHub Actions IP 대역 자체를 차단 → "Access Denied" (HTML 316바이트)
- 리다이렉트는 성공하지만 상품 페이지 접근에서 차단
- **결론: 서버사이드 스크래핑 불가 → 앱 포그라운드 WebView 방식으로 전환**
- 파트너스 API 키 발급 후 서버사이드 가격 조회로 전환 예정

## 핵심 결정사항

### Expo Push API 사용 (FCM 직접 아님)
- Expo managed workflow에서는 `expo-notifications`로 Expo Push Token 발급
- 서버에서 Expo Push API (`expo-server-sdk`)로 발송 → Expo가 FCM/APNs 대행
- @react-native-firebase/messaging 불필요 (CocoaPods 문제 회피)

### 가격 체크: GitHub Actions + Puppeteer
- 쿠팡이 서버 요청을 403 차단 → Puppeteer(headless Chrome)로 우회
- `puppeteer-extra-plugin-stealth`로 헤드리스 감지 회피
- CoupangScraper.tsx의 DOM 추출 로직을 Node.js용으로 포팅

### 포그라운드 가격 체크 흐름 (⚠️ 비활성화)
> iOS Universal Link 문제로 PriceChecker 비활성화. WebView가 coupang.com 로드 시
> 쿠팡 앱으로 자동 전환되는 문제를 모든 방법으로 우회 시도했으나 실패.
> onShouldStartLoadWithRequest, JS deeplink 차단, fetch+loadHTMLString 등 시도.

### 수동 새로고침 흐름 (현재)
1. 상세 페이지 헤더의 새로고침 아이콘 탭
2. `CoupangScraper`에 `resolvedUrl || url` 전달
3. Hidden WebView에서 DOM 스크래핑
4. 성공 시 `updateItemPrice()` (로컬 + Firestore)
5. 실패 시 Alert 표시, 15초 타임아웃

### Firestore 스키마 확장
```
users/{uid}
├── expoPushToken: string          ← 신규
├── notificationEnabled: boolean   ← 신규
└── items/{itemId}                 ← 기존 유지
```

### 알림 클릭 → 딥링크
- notification.data에 `{ itemId, screen: 'detail' }` 포함
- `addNotificationResponseReceivedListener` → `router.push('/detail/{itemId}')`
- 앱 종료 상태: `getLastNotificationResponseAsync()`로 초기 딥링크 처리
