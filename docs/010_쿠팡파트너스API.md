## 상태: ✅ 스크래핑 구현 완료 / ⏸ 파트너스 API 보류 (15만원 달성 후)

## 상품 정보 스크래핑 (WebView 방식)

### 배경: 서버사이드 스크래핑 불가
- 쿠팡은 모든 서버 User-Agent를 403으로 차단 (curl, fetch, 모든 UA)
- React Native에서 fetch()해도 200이지만 2KB 봇 차단 페이지 반환
- Google 캐시, Naver 검색 등 우회도 불가
- **해결: Hidden WebView에서 실제 브라우저 엔진으로 DOM 스크래핑**

### 구현 방식
1. `CoupangScraper.tsx` — 숨겨진 WebView (0x0 크기, opacity 0)
2. 쿠팡 URL 로드 → link.coupang.com 단축 URL도 자동 리다이렉트
3. `onNavigationStateChange`로 상품 페이지(`/vp/products/`, `/vm/products/`) 도착 감지
4. `onLoadEnd` 이벤트로 로딩 완료 감지 (수동 URL 입력 대응)
5. 2초 대기 후 `injectJavaScript(SCRAPE_JS)` 실행
6. DOM에서 추출: 상품명(OG → h2 → title), 가격(DOM → OG → JSON-LD), 이미지(OG → img)
7. `postMessage`로 React Native에 결과 전달
8. `price > 0` 체크 — 중간 페이지(리다이렉트)는 무시, price=0이면 재시도 허용

### 딥링크 차단
- `injectedJavaScriptBeforeContentLoaded`로 `window.location` setter override
- `coupang://`, `itms-appss://`, `intent://` 스킴 할당을 무시
- `app.json`에 `LSApplicationQueriesSchemes: ["coupang", "itms-appss"]` 추가

### 상품명 정리
- OG 타이틀에서 `|` 또는 `-` 이후 전체 제거: `title.replace(/\s*[|\-].*$/, '').trim()`
- 프로토콜 없는 이미지 URL 보정: `//xxx` → `https://xxx`

### URL 파싱 (수동 입력)
- 붙여넣기 시 "상품명\nURL" 형태 대응
- `extractUrl()` — 텍스트에서 `https://` URL만 정규식 추출

### 핵심 파일
| 파일 | 역할 |
|------|------|
| components/CoupangScraper.tsx | Hidden WebView + DOM 스크래핑 |
| app/modal/add-item.tsx | Share Intent / 수동 입력 → 스크래핑 → 저장 |
| services/productMeta.ts | 공유 텍스트 파싱 (fallback용, 레거시) |

### 실기기 테스트 결과
- ✅ Share Intent로 쿠팡 링크 공유 → 상품명/가격/이미지 정상 추출
- ✅ 플러스 버튼 URL 직접 입력 → 스크래핑 정상 동작
- ✅ link.coupang.com 단축 URL → www.coupang.com 리다이렉트 후 스크래핑 성공
- ✅ 이미지 렌더링 (목록 + 상세 화면)

## 파트너스 실적 미집계 원인 확정 및 조치 (2026-04-20)

### 공식 확정 (쿠팡 파트너스 가이드 p.13)
> "쿠팡 내 공유 기능 사용 링크는 수익 집계 안 됨"

공식 가이드에서 `link.coupang.com/a/...` 단축 공유 URL은 **수익 집계 대상이 아님**을 명시.
→ 기존 구조(공유 URL을 그대로 저장)로는 구조적으로 수수료 발생 불가.
→ **Firebase Functions 서버사이드 resolve로 근본 해결 필수** (018 번호로 착수).

아이고 앱(형제 앱, AQ-4)도 동일 문제 확인 — 공통 해결책 필요.

### 근본 원인 (실측)
공유 단축 URL `link.coupang.com/a/...`가 **iOS Universal Link로 선제 흡수**되면서 `add-item.tsx:125` `fetch(parsedUrl, { redirect: 'manual' })`가 `Location` 헤더를 얻지 못함
→ `resolved`가 `link.coupang.com/a/...` 그대로 유지
→ `resolved.includes('/vp/') || resolved.includes('/vm/')` 조건 불통과
→ **`generateDeepLink` 미호출 → 원본 공유 URL 그대로 저장 → 수수료 트래킹 끊김**

### 임시 수정 (커밋 `673c601`, 1.0.4 bn37/vc37)
- `add-item.tsx` 딥링크 생성 조건을 `resolved.includes('coupang.com')`로 완화
- `handleNext`(L142) + `handleSave`(L247) 두 지점 모두 적용
- **한계**: `link.coupang.com/a/...`는 이미 단축된 파트너스 링크 → `/deeplink` API가 원본 URL(`www.coupang.com/vp/...`)을 기대하므로 `rCode !== '0'`로 실패 가능성 높음
- 실패해도 폴백(원본 URL 유지)은 유지되므로 앱 동작에는 무해. **로그 `[CoupangAPI] 딥링크 응답: <rCode>`로 실제 성공률 검증 필요**
- 검증 지표: `link.coupang.com/a/...` 입력 시 `shortenUrl`이 생성되면 성공, `null`이면 실패

### 근본 해결책: Firebase Functions Resolver (2026-04-21 착수 확정)
- **상세 작업 MD**: `docs/018_FirebaseFunctions_Resolver.md` — 내일 착수, 6단계 순서 명시
- **핵심 설계**:
  - Firebase Functions `resolveAndGenerateAffiliateUrl` (jigumiya 프로젝트, asia-northeast3)
  - 입력: `{ sharedUrl }` → 서버 `fetch`로 302 리다이렉트 체인 추적 (최대 5회, 루프 방지)
  - Safari 모바일 User-Agent 고정 (쿠팡 봇 차단 회피)
  - resolved URL로 `/deeplink` API 호출 → `shortenUrl` 반환
- **핵심 전제**: iOS Universal Link는 클라이언트에서만 발동 → 서버 fetch는 영향 없음
- **클라이언트 변경**: `add-item.tsx`에서 `generateDeepLink` 직접 호출 대신 Functions 엔드포인트 호출 (초기엔 실패 시 클라이언트 fallback 유지)
- **부가 효과**: 쿠팡 API 키 노출 제거 가능 (2차 정리 단계)
- **Phase 3-C 인프라 기반**: 첫 서버사이드 엔드포인트 → 이후 shared_products 관리/가격 체크 이관의 기반
